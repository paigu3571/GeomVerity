# GeomVerity · 几何求真

开源工程语义与可信AI框架 · 从几何数据，到可信工程决策。

参赛名称：《面向建筑机电设计的CAD语义解析与可追溯自动化框架》

## 1 问题与场景

建筑底图换了，电气工程师需要立即知道：哪里要重做，过去的确认还能不能用。

设计院的墙、门、房名和修改记录分散在CAD里。工程师看得懂图，程序却难以把“房间、出入口、邻房”持续对应起来；图纸换版后，原来的出口确认和布灯结果容易被继续沿用。另一个断点出现在AI建议里：结论看起来完整，输入对象、规则版本和判断过程却难以逐项核查。

GeomVerity把这两个断点接到同一条工程证据链上：从真实CAD对象提取空间语义，跟住版本变化，再把需要复核的事项、生成对象和出处交给工程师。

## 2 技术方案与优势

让代码负责能算清楚的部分，让模型提出语义与协作建议，让工程师批准专业结论。

<!-- architecture -->

L1—L2图元与几何解析采用确定性代码；L3围合与拓扑由代码完成，术语由LLM提议、工程师批准后进入词表；L4检查、计算和布置由规则执行，LLM起草规则及变更通知并接受引用校验。识别核心保持独立，Viewer只展示后端的风险排序和决策依据。

第一层价值是自动协作：删门后优先提醒出口复核；设备房改成水泵房后，提示贴邻机房的防水提资；房间改了，旧确认按依赖指纹失效，灯具候选随之重生成。通知保留房名、Handle和版本时间，工程师可以直接核对、签字和转发。

第二层价值是打开AI盲盒：数据能追到源图对象，规则能追到条款与版本，AI提议能追到请求、回答、校验和审批。工程决策记录把这三层来源放在一起，供人和下游程序共同使用。

## 3 实现情况

真实宿主、真实工程平面和真实改图记录已经进入同一条可运行流程。

AutoCAD/T20插件已完成两图实扫，公开快照A/B分别有73/48个空间。四条机房条件示例规则已接入；三间配电房出口条件由张田核对后，本项数量初查满足。换版演示能够高亮改动、定位源Handle、提示失效确认，并输出独立灯具候选DXF和待签字协作通知。

8项人工改图记录：首次冻结输出对照为6项对应、1项部分、1项不一致；人工记录房名笔误更正后为7项对应、1项部分。历史六问首答校验3/6，重答后5项通过、1项被拦截。术语实测中，原关键词未覆盖的46种名称，模型为42种提出类别、4种保留UNKNOWN；提议经工程师批准后采用，工程师审核后启用45/46种原关键词未覆盖名称，详细对照见仓库。MCP七个只读工具已由真实客户端调通，SDK普通安装已验证。

两名工程师单次对照中，传统人工组40分钟发现5/8；工具组含扫描约10分钟发现8/8。这是两人各一次的观察，完整条件与程序冻结记录分别公开。

Python核心可离开Viewer与Desktop运行。插件本身也是工业软件的交付形态：本项目保留工程师正在使用的CAD入口，独立核心承担换版分析、规则与证据输出。

当前范围：少量单层样例，不能外推整图识别准确率；跨楼层与部分专业资料仍缺失。壁灯是布置候选，有效闭合房间按演示参数计算LPD并估算平均照度，异形房间使用实际面积和周长计算房间指数。术语与通知中的专业判断、最终设计签字仍由工程师完成。

自有代码采用MPL-2.0，著作权人、原作者及维护者为张田；第三方保留原许可。开源包包括识别核心、Python规则/AI层、示例规则、脱敏JSON和真实调用缓存；不包含原DWG、密钥、内部业务规则或内部接口。许可证、依赖声明、贡献流程和自动检查随代码交付。

## 5 后续维护计划

把规则、术语和决策证据积累为工程师能够共同维护的资产。

张田负责维护与发布，龙宇负责专业规则审核。Issue在7个工作日内响应，计划每月发布一个小版本。项目使用AI辅助开发工具，改动通过测试和可复现样例验收。工程师可提交带条款出处的规则与术语提议，获批后才参与执行。后续优先跨层数据与更多实测，再扩展机电图元及专业规则。与FreeCAD侧重3D参数建模的平台路径互补，GeomVerity先打通既有CAD提资中的工程理解与协作证据。
