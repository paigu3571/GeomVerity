# 工程师怎样贡献规则
先用日常工程语言描述“哪个房间，在什么条件下，需要检查什么”。提供规范名称/版本、条号、原文的合法来源及使用范围，不把公司规定当国家规范。

不用安装编程工具：可通过规则Issue提交条文和三个小例子，维护者将其转为rules/drafts下YAML。草案必须含id、title、clauses、applies_to、check、on_missing、scope；approved先为false。

工程师核对：出处是否正确，房间分类是否适用，候选输入是否需要复核，“应/宜”是否正确，缺资料的结果是否诚实。通过后由维护者填写approved:true、approved_by并合并PR；不得由AI自动审批。

现有六种判断条件只能表达用途、长度阈值、出口数、贴邻、上下层、共井。表达不了时明确需要新增判断条件，不强行拼凑。新增规则必须附通过/不满足/资料缺失测试和来源说明；真实样例数字另行评测，不能用合成测试冒充准确率。
