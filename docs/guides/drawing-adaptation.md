# 图纸适配与社区贡献

GeomVerity用公开的数据契约连接CAD输入与下游分析。不同单位可以保留自己的图层和制图习惯，通过适配配置接入；社区逐步积累有验证记录的配置。项目不会预先覆盖所有图纸标准。未识别出的内容应先登记为覆盖缺口，不据此断言其不存在。

## 先选运行入口

|目的|需要什么|当前范围|
|---|---|---|
|查看图面、变化与证据|浏览器打开在线演示或离线HTML|不需要CAD、天正和API密钥|
|重算公开样例|Python 3.11及依赖、配套JSON；内存要求见README|不需要CAD、天正和API密钥；输入必须符合现有契约|
|扫描自己的DWG|合法安装的宿主、插件、适合本图的配置|实测宿主为Windows上的AutoCAD 2016＋T20 V8；其他组合待验证|

样例重放验证的是分析核心和证据流程。扫描自己的图纸还要验证宿主、对象读法与制图配置。评测记录分开保存，不能由前一项推定后一项已经通过。

## 哪些地方会受制图习惯影响

|环节|现有做法|换标准时要检查什么|
|---|---|---|
|L1采集|保存原始对象、图层、Handle、实例路径与几何|宿主是否读得到对象，代理对象是否有解释器，块与外参是否可解析|
|L2解释|天正对象优先按原生类型解释；普通图元结合类型、图层和块名判断|墙、门窗是否保持原生对象，普通线条是否能被解释为所需对象|
|L3空间|几何拓扑结合配置中的图层、房名和规则建立空间|房名层、面积层、围合方式、单位和术语是否匹配|
|Python与L4|读取配套JSON，运行比较、规则与候选生成|对象和关系是否齐全、用途是否获批、专业条件是否补齐|

例如，天正墙的类型仍是TDbWall时，改一个图层名未必影响墙类型识别；但把房名从默认配置使用的层移到其他层，可能使房名与围合的关联失效。普通线条画的墙还涉及线条如何组成墙体，单纯改图层映射未必足够。模型术语提议帮助理解新房名，不能恢复不可读取的原生几何。

默认文件为[generic.project-profile.v1.json](../../cs/profiles/generic.project-profile.v1.json)。文件里的“generic”和“通用”表示随附默认入口，不代表已经验证所有单位的标准。它包含S-COLU、X-Asst、A-Spac-Iden-Auto等具体约定，使用者需要核对。

## 初次接入自己的图纸

1. 记录CAD、天正的完整版本与补丁号、插件构建版本、输入单位及对象类型。其他版本先标“未验证”；目录和文件名可以自定。
2. 从默认配置复制一份自用配置，保留原文件。先列出墙、柱、门窗、房名、面积等图层与块名，对照layer_normalization和geometry_semantic_rules；两者解决的环节不同，须分别验证。
3. 使用JZBP_PROFILE明确指定自用配置。配置可以放在自选目录，图纸无需移到该目录。环境变量示例见下方。
4. 保存DWG后按[CAD构建与加载](cad-build.md)扫描。核对原生对象、几何、房间和诊断；若没有识别到预期机房，先查来源、图层、术语和围合，不继续据此判断“图上没有机房”。
5. 用工程师已知的小范围答案核对：哪里是房间、哪个是门、哪些是井；比较墙、门、房间数量与漏项，检查Handle和实例路径能否回到源图。检查数量不能代替正确率。0个机房或0条检查结果不能作为全图通过。
6. 引用链、几何与用途核对后，再用于规则检查和版本分析。先补齐本次功能依赖的输入，未核对的范围保留记录。

复制并编辑好自用配置后，在该文件所在目录的PowerShell中执行：

```powershell
$taskProfile = (Resolve-Path -LiteralPath './my-style.project-profile.v1.json').Path
$env:JZBP_PROFILE = $taskProfile
[Environment]::SetEnvironmentVariable('JZBP_PROFILE', $taskProfile, 'User')
```

文件名是示例，请换成已存在的自用配置文件。当前PowerShell及其后续启动的CAD会继承该设置；用户变量用于以后的新进程。已打开的CAD需重新启动。切回默认配置时清除当前进程和用户变量，再重新启动CAD：

```powershell
Remove-Item Env:JZBP_PROFILE -ErrorAction SilentlyContinue
[Environment]::SetEnvironmentVariable('JZBP_PROFILE', $null, 'User')
```

如另设了JZBP_PROFILE_ROOT，查找仍会优先使用该目录；要恢复随插件默认配置，还需清除自设的目录变量。

配置决定识别约定，不替代CAD／天正对象解释器。更换宿主版本可能需要适配SDK与运行时；已有DLL不自动获得跨版本兼容性。

## 遇到缺口，需要补什么

|现象或已有诊断|优先核对／补齐|补齐后如何验证|
|---|---|---|
|T20_INTERPRETER_REQUIRED、UNSUPPORTED_PROXY_OBJECT|匹配的天正环境或对象解释能力；记录未识别对象类型|在目标宿主中重扫，核对原生对象与几何；不以改图层名替代解释器|
|T20_NATIVE_GEOMETRY_UNAVAILABLE、INVALID_GEOMETRY|原生几何读取支持及异常对象的小样例|检查精确路径与引用；不把代理包围盒当作有效墙体或房间|
|PROFILE_INVALID、UNIT_PROFILE_REQUIRED、UNIT_MISMATCH|有效配置、图纸单位与换算依据|核对已知尺寸后重扫|
|扫描完成但墙、门或房间数量异常|图层／块名映射、普通图元解释方式、局部人工答案|逐层查看L1、L2、L3，确定缺失发生在哪一层|
|KNOWN_SPACE_LABEL_UNRESOLVED或查看器的围合问题|房名位置、图层关联、墙门围合与区域语义|定位源图核对后重扫；不要求为了程序修改本来正确的图纸|
|能找到房间但用途未知|术语提议与工程师确认|批准前保留未知，不把它当“不适用”或“通过”|
|能检查本层，但缺上一层或专业做法|对应楼层、邻房完整性与防水等专业资料|补齐输入后重新执行对应规则|

上述代码中已有的诊断和查看器问题定位可以帮助排查。完整的自动图层盘点、缺口覆盖率以及统一的“未适配项—所需输入—复验步骤”报告尚未实现，列为后续接入工作；当前用本表与适配Issue登记。程序也不能可靠列出所有自己没有发现的对象，漏检仍需要工程师的小范围答案来核对。

## 社区怎样完善适配库

库按四种内容分开维护：

|内容|当前位置|贡献方式|
|---|---|---|
|宿主与原生对象读取|cs/src/及宿主验证记录|提交版本组合、最小复现与适配代码，单列真实加载／扫描结果|
|图层与制图配置|cs/profiles/|提交独立ProjectProfile文件，说明图层约定、适用对象与验证范围|
|工程术语|rules/中的用途词表与术语提议|保留模型原提议和人工采用结果，经工程师批准后启用|
|专业规则|rules/中的规则文件|按规范、版本、条号、条件及案例贡献，经专业审核后执行|

先提交[图纸／宿主适配Issue](../../.github/ISSUE_TEMPLATE/adaptation.md)，工程师不需要先写代码。维护者协助把图层对照和样例整理成配置；涉及新原生对象类型或SDK时，再进入代码适配。

每份贡献至少带：

- 环境：宿主、天正、插件和配置版本，单位与图纸类型。
- 对照：原始图层／块名、预期类别、采用的映射；适用及不适用对象。
- 样例：有授权的脱敏最小数据或合成数据、人工答案、预期识别与预期拒绝的例子。合成数据标SYNTHETIC；不能代替真实宿主实测。
- 证据：识别数、漏项、引用核查、验证方式、日期与确认人。未实测的环境明确登记“未验证”。

提交时保留贡献者权利，注明数据与第三方来源；不上传原工程DWG、密钥、专有配置或未经授权的资料。独立新增配置，不直接改写已有冻结配置和A/B样例。验证记录可放在docs/acceptance/，不要把未约定的兼容性字段塞进现有严格JSON契约。

维护者核对格式、来源和回归，工程师核对专业含义，随后合并并发布。记录“提议中／离线样例已验证／指定宿主已验证”等实际状态；未提供实测证据的组合仍为“未验证”。新配置经过的测试不得推定为所有图纸都适用，原有配置继续保留适用边界与版本。

## 下一步建设方向

优先形成可复用的图层配置、小范围人工答案和宿主兼容性记录，再补自动盘点与缺口提示；评估新的宿主版本时分别构建、分别测试。社区贡献一份已验证的适配包，就增加一条有出处的接入路径，不要求维护者收集所有设计院的标准。

当前提交入口、配置机制与诊断已存在；完整预检器、配置自动推荐和跨宿主自动切换均为计划。已验证的范围见[宿主记录](../acceptance/cad-host-validation.md)，未来接入约定见[工程决策记录与外部接入](../architecture/traceability.md)。
